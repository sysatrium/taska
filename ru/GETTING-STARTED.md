# Пошаговый старт для новичка

Этот файл нужен для человека, который впервые открыл `taska` и хочет получить результат без хаоса.

Если вы новичок, не начинайте с кода.

Сначала пройдите шаги ниже строго по порядку.

## Что вы получите в конце

Если пройти этот путь последовательно, вы получите:

- заполненный discovery-контур или подтверждение, что он не нужен
- базовые project artifacts после bootstrap
- первую feature spec
- plan и tasks для первой фичи
- реализацию хотя бы одной задачи
- отдельную проверку результата через verify

## Главное правило

В этом репозитории нельзя прыгать сразу к этапу `Implement`.

Правильный путь такой:

`Discovery -> Bootstrap -> Specify -> Contract -> Plan -> Tasks -> Implement -> Verify -> Learn`

## Где запускать prompts

Это критично важно.

Новичок должен понимать, что сами `.md`-файлы не «запускаются» как скрипты.

Их нужно **открывать, копировать содержимое и вставлять в AI-инструмент**, который работает с вашим репозиторием.

### Лучший режим для новичка

Используйте AI-инструмент, который:

- видит файлы репозитория
- может читать и создавать файлы прямо в проекте
- умеет вносить изменения в рабочую директорию

Самый удобный режим:

1. открыть репозиторий в IDE
2. запустить AI-агента внутри IDE
3. открыть нужный prompt-файл
4. вставить его в чат агента
5. попросить агента выполнить prompt и сохранить результат в нужный файл

### Что использовать на практике

#### Вариант 1. Claude Code или похожий агент в IDE

Это лучший вариант для bootstrap, feature lifecycle и verify.

Почему:

- агент видит структуру проекта
- агент может читать существующие файлы
- агент может сразу создавать `spec.md`, `plan.md`, `tasks.md` и другие артефакты
- вы не тратите токены на постоянную вставку больших кусков уже существующего контекста

Используйте этот вариант для:

- `00-discovery/`
- `00-bootstrap/`
- `01-feature-lifecycle/`
- `02-maintenance/`

#### Вариант 2. Cursor / Copilot Chat / Codeium / другой IDE-агент

Тоже подходит, если агент умеет работать с файлами в проекте.

Главное условие: агент должен не просто отвечать в чате, а реально читать и обновлять файлы в репозитории.

#### Вариант 3. Отдельный LLM в браузере

Используйте только для дешёвых ранних размышлений, когда вы ещё не хотите подключать весь репозиторий.

Это нормально для:

- первичного обсуждения идеи
- выбора направления продукта
- грубого обсуждения сегмента
- черновых JTBD-гипотез

Но это плохой вариант для основного потока, потому что:

- модель не видит текущие файлы проекта автоматически
- вам придётся вручную копировать контекст
- легко потерять связь между чатом и артефактами
- вы начинаете тратить токены на повторную передачу одного и того же контекста

## Как не тратить лишние токены

Используйте простое правило.

### Выносите в IDE-агента всё, что связано с файлами проекта

Если задача должна:

- прочитать файл
- создать файл
- обновить файл
- проверить связность артефактов
- реализовать код по spec

то делайте это внутри IDE-агента, а не в отдельном браузерном LLM.

### Используйте отдельный LLM только для дешёвого мышления

Подходящие случаи:

- придумать 2–3 варианта сегмента
- обсудить формулировку Big Job
- быстро сравнить продуктовые варианты
- подготовить черновик вопроса пользователю

После этого итог всё равно нужно зафиксировать в артефактах репозитория.

### Не гоняйте один и тот же контекст по кругу

Плохой сценарий:

1. обсудили идею в одном LLM
2. потом вручную вставили всё в другой LLM
3. потом отдельно перенесли в IDE
4. потом ещё раз пересказали verifier-агенту

Хороший сценарий:

1. коротко подумали снаружи, если нужно
2. как только появилась рабочая версия идеи — переходите в IDE-агента
3. дальше вся работа идёт уже внутри репозитория

## Готовые фразы для старта

Ниже — короткие фразы, которые можно просто копировать в IDE-агента вместе с нужным prompt-файлом.

### 1. Старт discovery

Используйте вместе с `ru/prompts/00-discovery/01-run-prd-interview.md`:

```text
Помоги мне пройти этот prompt по шагам как новичку.
Задавай по одному вопросу за раз.
Не пропускай обязательные шаги.
Сохраняй результат в ru/specs/000-project-overview/discovery.md.
Если моих данных не хватает, помоги выбрать безопасный временный вариант и явно пометь его как допущение.
```

### 2. Сводка discovery

Используйте вместе с `ru/prompts/00-discovery/02-summarize-discovery.md`:

```text
Используй ru/specs/000-project-overview/discovery.md.
Собери структурированную сводку discovery.
Заполни summary ясно и коротко.
Если есть пробелы, вынеси их в открытые вопросы, а не придумывай ответы.
```

### 3. Выбор сегмента и jobs

Используйте вместе с `ru/prompts/00-discovery/03-generate-segments-and-jobs.md`:

```text
Используй discovery-артефакты проекта.
Сгенерируй top-3 реалистичных сегмента.
Объясни различия простыми словами.
Помоги выбрать один основной сегмент для старта.
Сохрани результат в ru/specs/000-project-overview/segments-and-jobs.md.
```

### 4. Рискованные предположения

Используйте вместе с `ru/prompts/00-discovery/04-rank-risky-assumptions.md`:

```text
Используй discovery-артефакты и выбранный сегмент.
Выдели самые опасные предположения для MVP.
Для каждого предположения предложи дешёвый способ проверки.
Сохрани результат в ru/specs/000-project-overview/risks-and-assumptions.md.
```

### 5. Фиксация границ MVP

Используйте вместе с `ru/prompts/00-discovery/05-freeze-mvp-boundaries.md`:

```text
Используй discovery-артефакты проекта.
Зафиксируй MVP outcomes, must-have capabilities, out of scope и critical edge cases.
Если есть спорные места, оформи их как открытые вопросы или временные решения.
Сохрани результат в ru/specs/000-project-overview/mvp-boundaries.md.
```

### 6. Старт bootstrap

Используйте вместе с первым bootstrap prompt:

```text
Я новичок и хочу пройти bootstrap безопасно и по порядку.
Используй этот prompt и уже существующие discovery-артефакты, если они есть.
Создай или обнови нужный файл в репозитории.
Если тебе не хватает данных, сначала покажи 2–3 разумных варианта и порекомендуй самый безопасный.
Не перескакивай к следующему bootstrap-шагу, пока текущий не завершён.
```

### 7. Первая feature spec

Используйте вместе с `prompts/01-feature-lifecycle/01-create-feature-spec.md`:

```text
Помоги мне создать первую feature spec как новичку.
Возьми маленькую и безопасную фичу.
Не расширяй scope без необходимости.
Сделай spec достаточно конкретной для plan и tasks.
Если чего-то не хватает, зафиксируй это как open question или assumption.
```

### 8. План реализации

Используйте вместе с `prompts/01-feature-lifecycle/03-create-plan.md`:

```text
Построй plan только на основе утверждённой spec.
Не добавляй новые фичи от себя.
Покажи компоненты, data flow, риски и основные технические решения.
Сохрани результат в соответствующий plan.md.
```

### 9. Декомпозиция на задачи

Используйте вместе с `prompts/01-feature-lifecycle/04-create-tasks.md`:

```text
Разбей plan на маленькие задачи, которые можно делать по одной.
Для каждой задачи укажи ожидаемый результат и критерии приёмки.
Не делай задачи слишком большими.
Сохрани результат в tasks.md.
```

### 10. Реализация одной задачи

Используйте вместе с `prompts/01-feature-lifecycle/05-implement-task.md`:

```text
Реализуй только одну задачу из tasks.md.
Не выходи за её scope.
Если видишь проблему в spec или plan, сначала остановись и скажи об этом.
После реализации перечисли, какие файлы были изменены.
```

### 11. Verify одной задачи

Используйте вместе с `prompts/01-feature-lifecycle/06-verify-task.md`:

```text
Проверь только что выполненную задачу как verifier.
Ищи несоответствия spec, выход за scope, пропущенные edge cases и слабые места в качестве.
Если найдёшь проблему, укажи severity и объясни, в чём дефект.
Не исправляй код молча — сначала покажи вывод проверки.
```

## Самый безопасный путь для новичка

Ниже — маршрут, который можно просто выполнять по шагам.

### Шаг 0. Откройте репозиторий

Сделайте это сначала:

1. откройте репозиторий `taska` в вашей IDE
2. убедитесь, что видите папки `prompts/`, `specs/` и `ru/`
3. откройте AI-агента внутри IDE
4. откройте файл `ru/README.md`
5. затем откройте этот файл `ru/GETTING-STARTED.md`

Результат шага:

- репозиторий открыт
- агент подключён
- вы понимаете, где лежат prompts и куда должны записываться результаты

### Шаг 1. Решите, нужен ли discovery

Спросите себя 5 вещей:

1. Я точно понимаю, какой продукт или фичу хочу сделать?
2. Я понимаю, для какого сегмента это делается?
3. У меня есть Big Job и Core Jobs?
4. Я понимаю, что входит в MVP?
5. Я понимаю, что сейчас точно вне скоупа?

Если хотя бы на 2 вопроса ответ «нет», начинайте с discovery.

Если почти всё уже ясно, можно идти сразу в bootstrap.

### Шаг 2А. Если нужен discovery — пройдите его полностью

Откройте папку:

`ru/prompts/00-discovery/`

Дальше идите строго по файлам сверху вниз.

#### 2А.1. `01-run-prd-interview.md`

Что делать:

1. откройте файл
2. скопируйте его текст в чат IDE-агента
3. добавьте короткую команду: `Помоги пройти этот prompt по шагам и сохраняй результат в ru/specs/000-project-overview/discovery.md`
4. отвечайте агенту на вопросы по одному
5. доведите интервью до конца

Результат:

- появляется или обновляется `ru/specs/000-project-overview/discovery.md`

#### 2А.2. `02-summarize-discovery.md`

Что делать:

1. откройте файл
2. отправьте его в чат агента
3. попросите: `Собери структурированную сводку на основе discovery.md и обнови этот файл`

Результат:

- в `discovery.md` появляется структурированная summary-часть

#### 2А.3. `03-generate-segments-and-jobs.md`

Что делать:

1. откройте prompt
2. отправьте его агенту
3. попросите сгенерировать top-3 сегмента и выбрать один рабочий вариант
4. подтвердите выбранный сегмент

Результат:

- обновляется `ru/specs/000-project-overview/segments-and-jobs.md`

#### 2А.4. `04-rank-risky-assumptions.md`

Что делать:

1. откройте prompt
2. отправьте его агенту
3. попросите выделить top рисков и дешёвые способы проверки
4. сохраните результат в соответствующий файл

Результат:

- обновляется `ru/specs/000-project-overview/risks-and-assumptions.md`

#### 2А.5. `05-freeze-mvp-boundaries.md`

Что делать:

1. откройте prompt
2. отправьте его агенту
3. попросите зафиксировать MVP outcomes, must-have, out of scope и edge cases

Результат:

- обновляется `ru/specs/000-project-overview/mvp-boundaries.md`

### Шаг 2Б. Если discovery не нужен — зафиксируйте это явно

Если вы пропускаете discovery, напишите себе короткое решение в любом рабочем документе проекта:

- сегмент уже понятен
- MVP уже определён
- ключевые риски уже известны

Это нужно, чтобы потом не возник вопрос, почему discovery был пропущен.

### Шаг 3. Запустите bootstrap

Теперь переходите к базовой настройке проекта.

Откройте папку:

`prompts/00-bootstrap/`

Идите строго по порядку файлов.

#### 3.1. `01-create-constitution.md`

Что делать:

1. откройте prompt
2. отправьте его IDE-агенту
3. попросите заполнить constitution на основе уже известных решений и discovery-артефактов
4. проверьте результат

Результат:

- появляется `.specify/memory/constitution.md`

#### 3.2. `02-create-agents.md`

Что делать:

1. откройте prompt
2. отправьте его агенту
3. попросите создать `AGENTS.md` и связанные agent instructions

Результат:

- появляются agent operating rules

#### 3.3. `03-create-project-overview.md`

Что делать:

1. откройте prompt
2. отправьте его агенту
3. попросите использовать discovery-артефакты, если они есть

Результат:

- обновляется `specs/000-project-overview/`

#### 3.4. `04-create-sdd-structure.md`

Что делать:

1. откройте prompt
2. отправьте его агенту
3. попросите создать недостающую структуру каталогов и шаблонов

Результат:

- структура репозитория доведена до рабочего состояния

#### 3.5. `05-create-operational-prompts.md`

Что делать:

1. откройте prompt
2. отправьте его агенту
3. попросите создать или обновить operational prompts

Результат:

- bootstrap завершён

### Шаг 4. Проверьте bootstrap gate

До первой фичи убедитесь, что у вас есть:

- `.specify/memory/constitution.md`
- `AGENTS.md`
- `specs/000-project-overview/spec.md`
- discovery-артефакты, если вы проходили discovery

Если чего-то нет, не переходите к реализации.

Сначала закройте пробел.

### Шаг 5. Возьмите одну маленькую фичу

Новичку нельзя начинать с большой функции или с целого продукта.

Возьмите одну небольшую фичу, которую можно описать и проверить отдельно.

Примеры нормального первого объёма:

- форма входа
- одна CRUD-операция
- один API endpoint
- одно простое UI-взаимодействие

### Шаг 6. Создайте feature spec

Откройте папку:

`prompts/01-feature-lifecycle/`

Делайте по порядку.

#### 6.1. `01-create-feature-spec.md`

Попросите агента создать spec для одной конкретной фичи.

В spec должны быть понятны:

- outcome
- scope
- out of scope
- constraints
- assumptions
- verification criteria

#### 6.2. `02-create-api-contract.md`

Запускайте, если у фичи есть API или контракт взаимодействия.

#### 6.3. `03-create-plan.md`

Попросите агента собрать план реализации.

#### 6.4. `04-create-tasks.md`

Попросите декомпозировать работу на маленькие задачи.

Результат шага:

- у вас есть spec
- есть plan
- есть tasks
- можно переходить к одной конкретной задаче

### Шаг 7. Реализуйте только Task 1

Не просите: `реализуй всю фичу`.

Просите только одно:

`Реализуй Task 1 из tasks.md и не выходи за его scope.`

Используйте:

- `05-implement-task.md`

После этого остановитесь.

Не переходите к Task 2 автоматически.

### Шаг 8. Сразу запустите verify

Теперь откройте:

- `06-verify-task.md`

Попросите verifier-агента проверить только что сделанную задачу.

Он должен проверить:

- соответствие spec
- соответствие task description
- out of scope
- edge cases
- безопасность
- acceptance criteria

Если найден дефект, сначала поймите, где проблема:

- в коде
- в spec
- в plan
- в task decomposition

Только потом вносите исправление.

### Шаг 9. Только теперь переходите к Task 2

Если verify пройден, повторите тот же цикл для следующей задачи.

То есть каждый раз:

1. implement одной задачи
2. verify этой же задачи
3. только потом следующая задача

### Шаг 10. После инцидента обновляйте артефакты

Если после релиза или тестирования возникла проблема, не делайте только patch fix.

Откройте `prompts/02-maintenance/` и обновите:

- spec
- constraints
- verification criteria
- constitution, если проблема системная

## Самый короткий сценарий для первого результата

Если вы хотите получить первый результат максимально безопасно, делайте так:

1. откройте репозиторий в IDE
2. подключите IDE-агента
3. решите, нужен ли discovery
4. если нужен — пройдите весь `ru/prompts/00-discovery/`
5. выполните весь `prompts/00-bootstrap/`
6. возьмите одну маленькую фичу
7. выполните `01-create-feature-spec.md`
8. выполните `03-create-plan.md`
9. выполните `04-create-tasks.md`
10. реализуйте только Task 1
11. запустите verify

Этого уже достаточно, чтобы пройти полный мини-цикл и получить реальный результат.

## Частые ошибки новичка

Не делайте так:

- не запускайте prompts в случайном порядке
- не используйте браузерный LLM как основное место работы с файлами
- не просите агента сделать весь продукт за один раз
- не пропускайте verify
- не держите важные решения только в чате
- не исправляйте инциденты только в коде

## Быстрое правило выбора инструмента

Используйте эту формулу:

- если нужно думать без файлов — можно отдельный LLM
- если нужно работать с файлами проекта — только IDE-агент
- если нужно создать или изменить артефакт в репозитории — только IDE-агент
- если нужно писать код по spec и потом проверять — только IDE-агент

## Что читать первым, вторым и третьим

Если вы совсем новичок, читайте в таком порядке:

1. `ru/GETTING-STARTED.md`
2. `ru/README.md`
3. нужную папку prompts для текущего этапа

После этого уже начинайте работать по шагам из этого файла.
