# Спецификация проекта верхнего уровня

## Статус

Черновик

## Назначение

Описать продукт на системном уровне до начала реализации конкретных фич.

## 1. Миссия продукта

Опишите основное назначение системы, для кого она создаётся и какой значимый результат должна обеспечивать.

## 2. Основные акторы

Перечислите ключевые типы пользователей, операторов, администраторов, внешние системы и других важных участников.

Для каждого актора зафиксируйте:

- цели
- ключевые взаимодействия
- права или уровень доверия
- критичные ограничения

## 3. Ключевые сценарии

Опишите end-to-end сценарии, которые наиболее важны на уровне проекта.

Для каждого сценария зафиксируйте:

- триггер
- happy path
- основные точки принятия решения
- отказные или исключительные пути
- ожидаемый результат

## 4. Границы системы

Опишите, что входит внутрь системы и что сознательно остаётся за её пределами.

### В скоупе на уровне проекта

- Опишите первую capability или границу на уровне проекта.
- Опишите вторую capability или границу на уровне проекта.
- Опишите третью capability или границу на уровне проекта.

### Вне скоупа на уровне проекта

- Опишите первую исключённую capability или ответственность.
- Опишите вторую исключённую capability или ответственность.
- Опишите третью исключённую capability или ответственность.

## 5. Глобальные ограничения

Зафиксируйте ограничения уровня проекта, которые должны влиять на планирование всех фич.

- ограничения стека или платформы
- ограничения безопасности и compliance
- ограничения производительности
- ограничения поставки и rollout
- ограничения данных или интеграций

## 6. Нецели

Перечислите, чем проект точно не должен стать.

## 7. Метрики успеха

Определите измеримые признаки того, что проект успешен.

- пользовательские метрики результата
- delivery-метрики
- метрики качества
- операционные метрики

## 8. Системная проверка

Опишите, как проект будет проверяться за пределами feature-level приемки.

- критические пользовательские маршруты
- операционные проверки
- security validation
- ожидания по observability
- критерии готовности к релизу

## 9. Открытые вопросы

Перечислите неразрешённые вопросы уровня проекта, которые должны оставаться видимыми.
