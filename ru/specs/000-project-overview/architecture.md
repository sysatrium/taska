# Архитектурный обзор проекта

## Назначение

Зафиксировать верхнеуровневые архитектурные границы, модули, интеграции и ключевые tradeoff до начала feature-level планирования.

## 1. Контекст системы

Опишите место системы в более широком окружении.

- upstream-системы
- downstream-системы
- внешние зависимости
- точки взаимодействия операторов

## 2. Архитектурные границы

Опишите основные границы, которые должны направлять реализацию.

- доменные границы
- сервисные границы
- runtime-границы
- trust-границы
- deployment-границы

## 3. Основные модули

Перечислите главные модули или подсистемы.

Для каждого модуля зафиксируйте:

- ответственность
- входы и выходы
- зависимости
- владение
- риск изменений

## 4. Паттерны интеграции

Опишите, как модули и внешние системы взаимодействуют.

- sync vs async
- API style
- eventing или messaging
- retry и обработка отказов
- владение контрактами

## 5. Сквозные concerns

Зафиксируйте concerns, которые применяются ко всей системе.

- аутентификация и авторизация
- observability
- resilience
- конфигурация и секреты
- auditability

## 6. Ключевые ограничения

Перечислите архитектурные ограничения уровня проекта, которые должны соблюдаться в дальнейших планах.

## 7. Компромиссы и обоснование

Зафиксируйте основные tradeoff, уже принятые на уровне проекта.

- tradeoff
- обоснование
- принимаемая цена решения
- последствие для будущих шагов
