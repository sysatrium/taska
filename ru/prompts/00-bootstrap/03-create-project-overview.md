# Этап 0.3 — Создание проектного обзора

## Назначение

Создать верхнеуровневые проектные артефакты, которые определяют, что это за система, какие доменные объекты в ней существуют и какие архитектурные границы уже известны.

## Когда использовать

Используйте после утверждения конституции и до создания feature-спецификаций.

## Входные данные

- `.specify/memory/constitution.md`
- продуктовое видение и целевые пользователи
- известные доменные сущности и архитектурные ограничения

## Выходные файлы

```text
specs/000-project-overview/spec.md
specs/000-project-overview/data-model.md
specs/000-project-overview/architecture.md
```

## Что нужно сделать

1. Описать систему на уровне всего проекта.
2. Заполнить `spec.md` целями, актёрами, границами скоупа и ожидаемыми результатами.
3. Заполнить `data-model.md` ключевыми сущностями, связями, инвариантами и жизненными состояниями.
4. Заполнить `architecture.md` границами, модулями, интеграциями, ограничениями и важными компромиссами.
5. Согласовать все три файла с конституцией.

## Критерии готовности

Результат принимается только если:

- обзор проекта специфичен именно для этой системы
- модель данных выделяет значимые сущности и ограничения
- архитектурные границы достаточно явны для последующего планирования
- ни один файл не противоречит конституции
