# Этап 0.2 — Создание постоянного контекста агентов

## Назначение

Создать стабильные файлы операционного контекста, чтобы реализаторы и проверяющие агенты работали по одним и тем же правилам репозитория.

## Когда использовать

Используйте после создания `constitution.md` и до начала feature-работ.

## Входные данные

- `.specify/memory/constitution.md`
- соглашения репозитория, принятые на этапе инициализации
- ожидаемый способ использования AI-агентов и инструментов

## Выходные файлы

```text
AGENTS.md
CLAUDE.md
```

## Что нужно сделать

1. Сначала прочитать конституцию.
2. Создать `AGENTS.md` как постоянный контекст уровня всего репозитория.
3. Создать `CLAUDE.md` как компактную инструкцию для Claude Code.
4. Согласовать оба файла с конституцией.
5. Не дублировать длинные пояснения там, где достаточно короткого правила.

## Обязательное содержимое AGENTS.md

- назначение проекта
- канонический поток артефактов
- границы ролей агентов
- правила репозитория
- ограничения для реализации
- ожидания по проверке
- правила эскалации неоднозначностей

## Обязательное содержимое CLAUDE.md

- краткое операционное резюме
- команды или workflow-соглашения репозитория
- что Claude делать не должен
- как соблюдать границы спецификации и атомарность задач

## Критерии готовности

Результат принимается только если:

- оба файла согласованы с конституцией
- роли агентов разделены явно
- ожидания от реализатора и проверяющего заданы недвусмысленно
- правила эскалации неоднозначностей присутствуют
