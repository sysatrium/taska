# Этап 0.1 — Создание конституции проекта

## Назначение

Создать управляющую конституцию проекта, чтобы AI-агенты работали по устойчивым правилам, а не переобсуждали базовые договорённости в каждой задаче.

## Когда использовать

Используйте один раз в начале проекта, до появления feature-спецификаций, планов и реализации.

## Входные данные

- идея проекта и продуктовый замысел
- целевые пользователи и основные результаты
- предпочтительный стек или платформенные ограничения
- архитектурные предпочтения, если они уже известны
- ожидания по тестированию, безопасности и поставке

## Выходной файл

```text
.specify/memory/constitution.md
```

## Что нужно сделать

1. Провести интервью с человеком до начала записи файла.
2. Прояснить решения по стеку, архитектурным границам, правилам качества, безопасности и поставки.
3. Создать `constitution.md` как устойчивый набор правил для всех будущих агентов.
4. Предпочитать явные правила расплывчатым рекомендациям.
5. Неразрешённые вопросы фиксировать как открытые, а не додумывать.

## Обязательные разделы

- миссия проекта
- продуктовые результаты
- утверждённый стек
- архитектурные принципы
- соглашения по коду
- правила тестирования
- правила безопасности
- запрещённые паттерны
- правила поставки и релиза
- журнал решений или открытые вопросы

## Критерии готовности

Результат принимается только если:

- файл содержит конкретные правила, а не общий best-practice текст
- правила достаточно конкретны для ограничения дальнейшей реализации
- запрещённые паттерны указаны явно
- требования к тестированию и безопасности можно применить на практике
- неразрешённые вопросы видны как открытые

## Не переходить дальше, если

- конституция состоит в основном из заглушек
- критичные решения молча допущены
- архитектурные и качественные правила всё ещё двусмысленны
