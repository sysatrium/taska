# Русскоязычные SDD-промпты

Эта папка содержит интерактивный набор промптов для запуска greenfield-проекта в подходе Spec-Driven Development.

Главная идея проста: не создавать пустую структуру механически, а последовательно пройти интервью с AI, принять ключевые проектные решения и получить осмысленные операционные артефакты. Спецификации становятся главным контрактом для AI-агентов, а код появляется только после прохождения цикла `Спецификация -> План -> Задачи -> Реализация -> Проверка`.

## Для чего нужна эта папка

`ru/prompts/` — это **человеко-ориентированный оркестрационный слой** русской версии репозитория.

Пользователь открывает файлы по порядку, запускает их в выбранном AI-инструменте, отвечает на вопросы, а затем просит AI создать или обновить перечисленные проектные артефакты.

Эта папка отличается от `ru/.github/prompts/`:

- `ru/prompts/` содержит интерактивные промпты для человека и пошагового построения SDD-системы.
- `ru/.github/prompts/` содержит короткие системные промпты для IDE и agent tooling.

На старте проекта достаточно `ru/prompts/`. Каталог `ru/.github/prompts/` лучше подключать позже, когда уже есть `constitution.md`, `AGENTS.md` и основные проектные правила.

## Как использовать

Запускайте промпты последовательно. Не переходите к следующему шагу, пока предыдущий шаг не создал ожидаемые файлы и не прошёл критерии готовности.

Рекомендуемый рабочий цикл:

1. Откройте нужный `.md` файл.
2. Скопируйте его содержимое в AI-инструмент.
3. Ответьте на вопросы AI.
4. Попросите AI создать или обновить указанные файлы.
5. Проверьте результат по секции `Критерии готовности`.
6. Зафиксируйте изменения в git.

## Карта этапов

### Этап инициализации

Эти промпты используются один раз при запуске нового проекта.

#### `00-bootstrap/01-create-constitution.md`

Создаёт:

```text
.specify/memory/constitution.md
```

Фиксирует базовые правила проекта: стек, архитектурные принципы, соглашения по коду, запрещённые паттерны, требования к тестированию, безопасности и поставке.

#### `00-bootstrap/02-create-agents.md`

Создаёт:

```text
AGENTS.md
CLAUDE.md
```

`AGENTS.md` — постоянный контекст для всех AI-агентов. `CLAUDE.md` — более короткая инструкция для Claude Code.

#### `00-bootstrap/03-create-project-overview.md`

Создаёт:

```text
specs/000-project-overview/spec.md
specs/000-project-overview/data-model.md
specs/000-project-overview/architecture.md
```

Эти файлы описывают систему на верхнем уровне: что строим, для кого, какие результаты важны, какие сущности есть в домене и какие архитектурные границы уже заданы.

#### `00-bootstrap/04-create-sdd-structure.md`

Создаёт структурную основу SDD:

```text
.specify/
specs/
specs/templates/
src/
SPEC_PROCESS.md
README.md
```

Также должен зафиксировать переиспользуемые шаблоны и соглашения по структуре фич.

#### `00-bootstrap/05-create-operational-prompts.md`

Опционально создаёт:

```text
.github/prompts/
```

Этот шаг нужен, если проект будет использовать библиотеки промптов для GitHub Copilot, Cursor, Claude Code, AWS Kiro или аналогичных инструментов.

### Этап жизненного цикла фичи

Эти промпты используются для каждой новой фичи или эпика.

#### `01-feature-lifecycle/01-create-feature-spec.md`

Создаёт:

```text
specs/NNN-feature-name/spec.md
```

Фиксирует результаты, разделы в скоупе и вне скоупа, ограничения, уже принятые решения, первичную декомпозицию и критерии проверки.

#### `01-feature-lifecycle/02-create-api-contract.md`

Создаёт контракты фичи, например:

```text
specs/NNN-feature-name/contracts/api-spec.yaml
specs/NNN-feature-name/contracts/data-schema.json
```

Фактический набор контрактных файлов зависит от архитектуры системы.

#### `01-feature-lifecycle/03-create-plan.md`

Создаёт:

```text
specs/NNN-feature-name/plan.md
```

Описывает, как именно будет реализована фича: компоненты, поток данных, технологические решения, изменения в базе данных, интеграции, риски и нефункциональные требования.

#### `01-feature-lifecycle/04-create-tasks.md`

Создаёт:

```text
specs/NNN-feature-name/tasks.md
```

Разбивает фичу на атомарные задачи. Каждая задача должна иметь тип, зависимости, затрагиваемые файлы, описание, критерии приёмки и способ проверки.

#### `01-feature-lifecycle/05-implement-task.md`

Используется реализатором для выполнения одной конкретной задачи из `tasks.md`.

Правило: один запуск — одна задача. Агент не должен незаметно расширять скоуп и реализовывать соседние задачи.

#### `01-feature-lifecycle/06-verify-task.md`

Используется проверяющим агентом после реализации.

Задача проверяющего агента — искать проблемы: несоответствие спецификации, изменения вне скоупа, нарушения конституции, пробелы безопасности, пропущенные пограничные сценарии и слабые тесты.

### Этап сопровождения

Используйте эти промпты после инцидентов, изменения плана или распада качественной декомпозиции.

#### `02-maintenance/01-update-spec-after-incident.md`

Обновляет спецификацию фичи после инцидента, чтобы система училась на реальных сбоях и добавляла недостающие ограничения, пограничные сценарии и правила проверки.

#### `02-maintenance/02-update-constitution.md`

Обновляет общепроектные правила, когда меняются стек, модель безопасности, модель поставки или архитектурные предпосылки.

#### `02-maintenance/03-refine-tasks.md`

Пересобирает `tasks.md`, если текущая декомпозиция оказалась слишком крупной, слишком расплывчатой, устарела или потеряла проверяемость.

#### `02-maintenance/04-run-pre-implementation-checklist.md`

Выступает жёстким рубежом готовности перед началом кодинга.

## Рекомендуемый порядок чтения

Если вы впервые открыли репозиторий, двигайтесь в таком порядке:

1. `ru/README.md`
2. `ru/GLOSSARY.md`
3. `ru/prompts/README.md`
4. `ru/prompts/00-bootstrap/*`
5. созданный `constitution.md`
6. созданный `AGENTS.md`
7. `ru/prompts/01-feature-lifecycle/*`
8. `ru/prompts/02-maintenance/*`

## Политика документации

Корень репозитория является каноническим источником правил. Каталог `ru/` — русскоязычное зеркало для human-facing использования. Если операционные правила меняются, сначала обновляйте корень, затем сразу синхронизируйте русскую версию.
